# Element System — Design & As-Built Documentation

> **📌 Статус:** ✅ Итерация 1 (ядро рисования); ✅ Итерация 2 (Земля-барьер); ✅ Итерация 3 (прочность Земли, per-cell HP) — **фича завершена**
> **🏷️ Ветка:** `phase2/element-system`
> **🎯 Результат:** Игрок применяет стихии к полю боя: выбирает алтарь в зоне базы, ведёт пальцем — рисуется линия применения (толщина настраиваемая). Стихии тратят ману, которая копится по алтарям независимо и наполняется от убийств монстров. Вода/Огонь/Воздух — временные слои; **Земля — непроходимый барьер** из ячеек с прочностью на ячейку: монстры атакуют и гибнут, прогрызая его.

## 📚 1. Терминология и обзор механики

| Термин | Описание |
|--------|----------|
| **Алтарь стихии** | Круглая иконка в зоне базы (Огонь, Вода, Земля, Воздух). Тап по алтарю **выбирает** (армит) стихию для рисования |
| **Мана алтаря** | Независимый запас каждого алтаря, с собственной ёмкостью и прогресс-баром. Источник — убийства монстров |
| **Рисование стихии** | После выбора алтаря палец ведётся по полю боя: рисуется линия (толщина = `radius`), списывается мана. **На препятствиях стихия не рисуется** |
| **Сегмент** | Одна нарисованная линия (штрих). У Воды/Огня/Воздуха исчезает со временем; у Земли — стойкий барьер (Итерация 2) |
| **Главная стихия (сила бога)** | Существующая механика (ГДД 2.5) — **НЕ трогаем**: полный заряд от молний, применение по тапу |

### Модель маны (as-согласовано, 10.09.2026)
- **Источник маны = убийства монстров.** Каждый убитый монстр даёт **каждому** алтарю свою порцию `gainPerKill` (может отличаться у разных алтарей).
- У каждого алтаря своя **ёмкость** `capacity` (независимая). Полный бар → мана больше не копится.
- Использование списывает `costPerUse` за **каждый юнит длины** (юнит = `elementStrokeUnit`, свой `costPerUse` у каждого алтаря); списание поюнитно в реальном времени. Применять можно при любом запасе, достаточном хотя бы на один юнит.
- Убийства учитываются только боевые (молния/супер сила). Монстры, дошедшие до базы (сняли HP и исчезли), ману **не** дают.
- Все параметры (`gainPerKill`, `capacity`, `costPerUse`, `radius`, `earth.bitesPerCell`) — конфигурируемые, прокачиваются в будущем.

### Поведение стихий (финальное)
| Стихия | Поведение |
|--------|-----------|
| **Вода** | Рисуется слой, fade по `duration`; урон/эффекты — бэклог |
| **Огонь** | Рисуется слой, fade по `duration`; урон/эффекты — бэклог |
| **Земля** | **Барьер из ячеек**: непроходим; монстры касаются → атакуют и гибнут, грызя ячейки (прочность `bitesPerCell`, кусок `biteRadius`); через дыры проходят |
| **Воздух** | Рисуется слой, fade по `duration`; урон/эффекты — бэклог |

## 🔌 2. Параметры баланса (конфигурируемые, будущая прокачка)

Каждой стихии в `GameConfig.elements` (кроме уже имеющихся `color/damage/duration/radius/cost`):

| Параметр | Описание | Прокачка |
|----------|----------|----------|
| `capacity` | Ёмкость маны алтаря (потолок накопления) | Да |
| `gainPerKill` | Порция маны алтарю за одного убитого монстра | Да |
| `costPerUse` | Цена за **один юнит длины** штриха | Да |
| `radius` | Толщина линии (радиус зоны применения), css-px | Да |
| `elementStrokeUnit` (общий) | Длина юнита штриха, css-px (дефолт 50) | Да |
| `earth.biteRadius` | Радиус «куска», который грызёт монстр за укус, css-px (24) | Да |
| `earth.bitesPerCell` | Прочность ячейки Земли: укусов держит (5); **прокачиваемый** | Да |

> **Дефолты (баланс):** `gainPerKill = 2`, `capacity = 20`, `costPerUse = 8`, `radius = 25` для всех четырёх стихий.

> Модель стоимости: линия наносится **сразу** (без предпросмотра), мана списывается **поюнитно в реальном времени**: за `N` нарисованных юнитов (каждый = `elementStrokeUnit`) платится `N × costPerUse`. Бюджет штриха = `floor(mana / costPerUse)` юнитов — дальше него линия не рисуется (обрыв в точке исчерпания маны). Неполный хвостовой юнит доплачивается при завершении (`ceil`).

### Персистентность настроек (TuningStore)
- Все параметры, настраиваемые в поп-апе ⚙ (спавн, генерация, сила бога, стихии, прочность Земли), сохраняются в **localStorage** (`fluid-crowd-defense.tuning.v1`) при каждом изменении (`updatePopupValues`/`setLevel`).
- Восстанавливаются в `create()` (`applyStoredTuning`) — **не сбрасываются** ни при смене уровня/перезапуске сцены, ни при перезагрузке страницы.
- `capacity` и `elementStrokeUnit` в поп-апе не настраиваются и не персистятся.

## 🔧 4. API

### ElementManaSystem (чистый TS, тестируемый без Phaser)

```ts
const mana = new ElementManaSystem(GameConfig.elements);

mana.manaOf('water');         // текущий запас маны алтаря
mana.capacityOf('water');     // ёмкость алтаря
mana.progress('water');       // 0..1 заполнение бара алтаря
mana.gainFromKills(n);        // убито n монстров -> порция каждому алтарю (cap)
mana.canUse('water');         // хватает ли маны на costPerUse
mana.use('water');            // списание costPerUse (если canUse)
mana.spend('water', amount);  // списание произвольной суммы (поюнитно)
mana.reset();                 // сброс всех запасов (новый уровень)
mana.onBalanceChanged();      // клэмп после изменения параметров

// Арм-состояние (выбранный алтарь для рисования)
mana.armed;                   // ElementType | null
mana.arm('water');            // выбрать стихию (true — можно рисовать)
mana.disarm();                // снять выбор
```

Инварианты: мана не превышает `capacity` (cap при накоплении); `use()`/`spend()` при нехватке ничего не списывают и возвращают `false`; `armed` не может указывать на стихию без доступной маны.

### ElementDrawer

```ts
new ElementDrawer(scene, isBlocked, onEarthStroke);
drawer.beginPotential(x, y, key, cfg, maxPaintedLength); // pointerdown
drawer.onMove(x, y);                                      // pointermove
drawer.end(): 'draw' | 'tap' | 'none';                    // pointerup
drawer.paintedLength / drawer.totalLength;                // для доплаты (settle)
drawer.cancel(); drawer.clearPersistent(); drawer.destroy();
```

- `isBlocked(x, y)` — коллизия в мировых координатах (препятствия не рисуются).
- `onEarthStroke(points)` — Земля-штрих отдаёт путь (сцена растеризует в барьер).
- `beginPotential` получает бюджет маны (`floor(mana/costPerUse)` юнитов) — дальше него линия не рисуется.
- Обработка жеста: `pointerdown` → потенциальный штрих (если алтарь выбран) либо молния; движение выше порога → рисование; `pointerup` без движения → `'tap'` (молния + disarm), без нарисованного → `'none'` (мана не тратится, выбор сохраняется).

## ⚙️ 5. Детали реализации (as-built)

### 5.1. Развод жестов «тап vs слайд»
- Тап по полю боя = молния/супер сила (существующая логика, без изменений).
- Тап по алтарю в зоне базы выбирает стихию (арм).
- После арма движение пальца по полю боя выше `controls.touch.swipeThreshold` считается рисованием; `pointerup` без движения — тап (молния) и disarm.
- **Выбор сбрасывается только тапом по полю (молния) или выбором другого алтаря.** После штриха (в т.ч. `none` — только по препятствиям) выбор **сохраняется**: можно рисовать куски в разных местах без повторного выбора.
- Поп-ап настроек по-прежнему перехватывает тапы (`settingsOpen` guard).

### 5.2. Препятствия не рисуются
- Рисование опрашивает коллизионную сетку уровня (`isBlocked` в мировых координатах) для каждой точки пути.
- **Начало над препятствием** — точка не рисуется; рисование стартует, когда палец выходит на свободное место.
- **Заход на препятствие во время штриха** — жест НЕ сбрасывается: на препятствии пауза, после выхода линия продолжается с нового сегмента.
- **Полностью над препятствием** — `end()` возвращает `none`: ничего не рисуется, мана не тратится, выбор снимается.

### 5.3. Мана: цена за длину, списание в реальном времени
- Линия наносится на поле **сразу** (без предпросмотра и последующего списания за штрих).
- `costPerUse` — цена за **юнит длины** (`GameConfig.elementStrokeUnit`, дефолт 50 css-px). За `N` юнитов — `N × costPerUse` (10 юнитов при цене 1 = 10 маны).
- Списание **инкрементальное**: на каждом `pointermove` пройденные юниты списываются (`spend`), бар убывает сразу (`chargeStrokeUnits`).
- **Бюджет**: на `beginPotential` = `floor(mana / costPerUse)` юнитов; дальше него drawer не рисует (стоп в точке исчерпания маны). Неполный хвостовой юнит доплачивается на `pointerup` (`settleStrokeUnits`, `ceil`).
- Препятствия не рисуются и не в счёт; полностью над препятствием — 0 маны, `end()` = `none`.

### 5.4. Визуализация слоя
- Каждый штрих — `Graphics` в цвет стихии, толщина `radius * UI_SCALE`, наносится **сразу** (без предпросмотра).
- Вода/Огонь/Воздух: слой плавно исчезает за `duration` мс (с момента отпускания).
- Земля (Итерация 2): превращается в барьер из ячеек (см. §5.8), отдельная Graphics.

### 5.5. Накопление маны
- `ElementManaSystem.gainFromKills(n)` вызывается в точках боевых убийств: `castLightning` и `castSuperAttack` (после подсчёта жертв).
- Рестарт уровня/зачистка пула (`restartLevel`) ману не начисляет.
- Сброс запасов — при смене уровня (`reset()`).

### 5.6. Алтари (UI)
- Алтари рисуются в `createElements()` (`ElementAltarIcon`): чёрный круг, заливка маны **цветом стихии снизу вверх** (механизм как у `GodPowerIcon`), кольцо-подсветка выбранного.
- **Доступность:** иконка и кольцо **яркие**, когда стихия выбрана ИЛИ маны хватает на штрих (`canUse`); **затемнены** (alpha 0.35), когда маны не хватает — независимо от степени заполнения бара. Прогресс-бар всегда виден.
- Полный алтарь — лёгкая пульсация заливки; выбранный — белое кольцо, увеличение, пульс.
- Перерисовка — событийная (`redraw`), не каждый кадр (паттерн `GodPowerIcon`).

### 5.7. Баланс в поп-апе настроек (⚙)
- **«Мана за убийство»** — `gainPerKill`, диапазон 0.1–2, шаг 0.1. Одна строка, применяет одинаковое значение **всем четырём алтарям** (конфиг остаётся per-altar для будущей прокачки).
- **«Стоимость огня/воды/земли/воздуха»** — `costPerUse` каждого алтаря отдельно, диапазон 1–100, шаг 1 (цена за юнит `elementStrokeUnit` px). После изменения вызывается `onBalanceChanged()` (снимает выбор, если стихия стала недоступна).
- **«Радиус штриха»** — общий `radius`, диапазон 10–100, шаг 5, применяется ко всем алтарям; действует со следующего штриха (читается на `beginPotential`).
- **«Убийств на заряд бога»** — `superChargeRequired`, 10–500, шаг 10 (выше = медленнее заряд); после изменения `godPower.onBalanceChanged()` + `godIcon.redraw()`. Дефолт 80 — заполнение в 2 раза медленнее прежнего (было 40).
- **«Прочность земли (укусов)»** — `earth.bitesPerCell`, 1–100, шаг 1 (выше = землю грызут медленнее); применяется к новым штрихам сразу (живое значение). Прокачиваемый атрибут.
- Панель: компактные строки (`rowHeight = fontPx(28)`), высота считается по числу строк (`rowCount = 18`), влезает на малых экранах.

### 5.8. Земля-барьер (Итерации 2-3, as-built)
- Земля = **набор ячеек коллизионной сетки** (`EarthBarrierSystem`) с **прочностью НА ЯЧЕЙКУ** (`bitesPerCell` укусов) — глобальной прочности нет, монстры прогрызаются.
- **Растеризация штриха:** путь из `ElementDrawer` (точки ± `radius`) → ячейки (`cellsWithinCircle`) → `addStroke`: ячейки получают HP = `bitesPerCell` (живое значение из конфига), `set_earth add` воркеру + перерисовка.
- **Визуал:** каждая ячейка — перекрывающийся круг `r ≈ 0.72·клетки`; **темнеет с потерей HP** (`k = hp / max`, плавный лерп к тёмной базе), исчезает при 0. Прогрызенные ячейки = дыры.
- **Воркер:** оверлей `earth` в `CollisionField`; `blockedAt` = препятствие ‖ земля; `earthAt`/`isBoxEarth` — контакт. В шаге до `moveDownStep`: хитбокс касается земли → `vx=vy=0`, id в канал `attacks` (`FrameMsg`). `moveDownStep` не менялся — паритет с fallback.
- **Атака (main):** id из `attacks` → `killEnemy` (БЕЗ маны и заряда бога) + `biteCellsAround(x, y, biteRadius·UI_SCALE)`: ячейки в радиусе теряют **1 HP** (чистая `biteCells`); при 0 → `set_earth remove` + перерисовка. Fallback-путь — тот же контакт в `updateEnemyMovement`.
- **Баланс:** `GameConfig.earth.biteRadius = 24` (ширина «куска» за укус), `bitesPerCell = 5` — **прокачиваемый атрибут** (выше = землю грызут медленнее; ручка в поп-апе «Прочность земли (укусов)» 1–100, экономика прокачки — будущее).
- **Сброс:** `set_level` обнуляет оверлей воркера; `generateLevel` пересоздаёт `EarthBarrierSystem`.
- Поведение: скорость потери ячеек = `монстры/сек ÷ bitesPerCell` → масштабируется под плотность; на высоких уровнях прочность поднимается прокачкой.

## ⚠️ 8. Риски и открытые вопросы

1. **Развод жестов** — порог слайда уже есть (`controls.touch.swipeThreshold`), но на мобильных возможны ложные срабатывания; проверить плейтестом.
2. **Земля в воркере** — динамическая модификация коллизионной сетки и события атак требуют аккуратного расширения протокола; гонки с кадровым буфером (как с `arrived`).
3. **Стоимость за штрих vs за длину** — решено: мана списывается **по длине в реальном времени** (юнит `elementStrokeUnit`, цена `costPerUse` за юнит), линия наносится сразу, при исчерпании маны — обрыв на границе юнита. Неполный хвост доплачивается (`ceil`).
4. **Мана за боевые убийства** — супер сила тоже наполняет алтари (это осознанно); при прокачке может понадобиться разное поведение.
