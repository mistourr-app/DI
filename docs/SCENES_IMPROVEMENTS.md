## 1. Что делаем и почему

Аудит подтвердил: функционально фича сделана аккуратно (чистая миграция, синглтон прогресса, sleep/launch, guard поп-апа поражения). Реально важных проблем две, остальное — укрепление.

| № | Проблема | Почему важна | Как решаем |
|---|---|---|---|
| **I1** | `UpgradeSystem.addSouls()` не сохраняет, флаш только на победе/покупке/ресете. Души за забег теряются при поражении, перезагрузке вкладки, закрытии PWA | Прямо противоречит `PROGRESSION.md §3` («души не отнимаются при GAME OVER»). Игрок теряет награду за забег | dirty-флаг, гарантированный сейв на game over, троттл-автосейв (по убийствам + по таймеру), сейв на `pagehide`/`visibilitychange`; бейдж «+N душ за забег» на экране поражения (`PROGRESSION.md §6`) |
| **I2** | `handleResize` пропускает спящую сцену (`if (!this.scene.isActive()) return`), но на `wake` геометрия не пересчитывается | Если окно изменилось, пока открыта `UpgradeScene` (ротация, клавиатура, адресная строка на мобильном), `GameScene` проснётся со старой `gameArea`/камерой, и следующий уровень сгенерируется по устаревшим размерам | обработчик `events.on('wake')`: если размер изменился — повторный `handleResize()`. ## 2. Решения по I1 (детали)

### 2.1 Модель сохранения

- В `UpgradeSystem` добавляется флаг `dirty`:
  - `addSouls()` начисляет души и ставит `dirty = true` (без записи в localStorage — как и раньше, чтобы не писать на каждое убийство);
  - `save()` пишет снимок и сбрасывает `dirty = false`;
  - `buy()/completeLevel()/reset()/resetAll()` продолжают сохранять сразу (они и так пишут);
  - новый геттер `hasUnsaved` — чтобы сцена понимала, нужно ли писать.
- Почему не «сохранять на каждый `addSouls`»: при плотности толпы это сотни записей в секунду в localStorage — лаг и износ. Троттл сохраняет и производительность, и надёжность.

### 2.2 Точки гарантированного сейва (GameScene)

| Точка | Зачем |
|---|---|
| **Поражение** (показ поп-апа `Deus mortuus est`) | Явное требование `PROGRESSION.md §3`: души за забег не теряются при GAME OVER |
| **Каждые N убийств** (`SOULS_SAVE_EVERY_KILLS = 25`) | Страховка от «убили вкладку» в середине забега |
| **По таймеру** (раз в `SOULS_SAVE_INTERVAL_MS = 5000`, если `dirty`) | Страховка при редких убийствах/паузах |
| **`pagehide` / `visibilitychange` (hidden)** | Мобильный PWA: сворачивание, закрытие, перезагрузка. Слушатели вешаются в `create()`, снимаются в `shutdown` |
| **Победа/вход в прокачку** | Уже есть: `completeLevel()` и `onSaveAndPlay()` (`progression.save()`) |

### 2.3 Бейдж «+N душ за забег»

- Поле `soulsRunStart`: души на момент старта забега (уровень 1).
  - `create()` — после восстановления прогресса/тюнинга;
  - `onDefeatRestart()` — после сейва и перед рестартом;
  - `resetAllProgress()` — обнуляется (души = 0).
- На поражении считаем `earned = progression.totalSouls - soulsRunStart` и показываем в поп-апе поражения подписью под заголовком.
- Почему на поражении: это награда «не потеряна» (`PROGRESSION.md §6`), и она видна там, где игрок мог бы решить, что всё пропало.

## 3. Решения по I2 (детали)

- `setupScreenZones()` сохраняет фактические размеры layout: `layoutWidth/layoutHeight`.
- В `create()` регистрируется `this.events.on('wake', this.onWake, this)`; в `shutdown` — `off`.
- `onWake()`: если `scale.gameSize` отличается от `layoutWidth/layoutHeight` — вызвать `handleResize(this.scale.gameSize)`.
- Почему сравнение с сохранёнными размерами, а не с `cameras.main`: Phaser может сам менять размер камеры при resize, и сравнение с камерой ложно показало бы «всё ок», хотя `gameArea`/зоны/база остались старыми.
- Двойная генерация: `UpgradeScene` сначала запускает следующий уровень, затем будит сцену; `onWake` при необходимости регенерирует уровень ещё раз уже с корректной геометрией. Переработка в «wake → затем генерация» не нужна: результат идемпотентен, а порядок перехода не меняет наблюдаемого результата.

## 4. Решения по I3 (детали)

- `layout.ts` перестаёт импортировать `phaser` и возвращает чистый интерфейс:
  ```ts
  export interface GameArea { x: number; y: number; width: number; height: number; }
  ```
- Оба сцены меняют тип `gameArea` на `GameArea` (используются только `.x/.y/.width/.height`).
- `layout.test.ts` проверяет:
  - широкий экран: поле по высоте, ширина кратна 16, центрирование по X;
  - узкий экран: поле по ширине, центрирование по Y (может уходить в отрицательный `y` — как и раньше);
  - граничный и «квадратный» кейсы;
  - монотонность/непрерывность по высоте (сетка без швов).

## 5. Решения по I4–I6 (детали)

- **I4a null-guard**: хелпер `getGameScene(): GameScene | null` в `UpgradeScene`; обработчики выходят, если сцена недоступна.
- **I4b шапка**: тестовая кнопка «↺ Сбросить прогресс» выносится в отдельную строку шапки (заголовок/души центрируются, кнопка ниже справа); `headerH` увеличивается, список начинается ниже — пересечения на узком поле исключены.
- **I4c маска**: `maskGraphics`/`mask` хранятся в полях и уничтожаются при `buildUi()` (resize) и в `shutdown`.
- **I4d дубль**: `onDefeatRestart()` не вызывает `closeEndPopups()` (это уже делает `restartLevel()`), либо наоборот — оставляем один вызов.
- **I5 e2e**: `jest.e2e.config.cjs` (testMatch только `e2e/**/*.e2e.ts`, timeout ~120 с) + `e2e/scenes.e2e.ts`: поднимает `vite` dev-сервер на `127.0.0.1:4173` (`base=/DI/`), ждёт готовности, гоняет Puppeteer-сценарий (победа → прокачка → покупка/индикатор → сохранить/играть; поражение → `+N` и рестарт на 1-й уровень), гасит сервер. Скрипт `test:e2e` направляется на `.cjs`-конфиг.
- **I6 eslint**: `.eslintrc.cjs` с `@typescript-eslint` (parser/plugin/extends), `env: browser+node`, `ignorePatterns: dist, node_modules, src/game/ecs`. Правила — так, чтобы существующий код давал 0 ошибок (`no-explicit-any` off, `no-unused-vars` warn, `no-undef` off для TS).

## 7. Критерии готовности

- Души, накопленные за забег, сохраняются при поражении и при закрытии/перезагрузке вкладки (проверяется смоуком: начислить души, вызвать game over, перечитать localStorage).
- На поп-апе поражения видно «+N душ за забег».
- После ресайза, пока открыта `UpgradeScene`, при возврате в геймплей геометрия (зоны, база, камера) и следующий уровень соответствуют новому размеру.
- `computeGameArea` покрыт unit-тестами (широкий/узкий/граница/кратность 16/центрирование).
- Шапка `UpgradeScene` на узком поле не пересекается с тестовой кнопкой.
- `npm run test:e2e` реально запускает e2e-сценарий (не падает на отсутствующем конфиге).
- `npm run lint` завершается успешно (без ошибок).
- `tsc --noEmit`, `npm test`, `npm run build` — без регрессий.
