# Game Design Document: Fluid Crowd Defense

## 1. Обзор игры

**Название:** Fluid Crowd Defense  
**Жанр:** Стратегия с видом сверху  
**Платформа:** PWA (Progressive Web App)  
**Целевая аудитория:** Игроки, интересующиеся стратегиями и физическими симуляциями

**Краткое описание:**  
Игра, в которой игрок защищает базу от орд врагов (до 1000 на экране), используя систему комбинируемых стихий. Враги ведут себя как жидкость - плавно обтекают препятствия.

## 2. Основные механики

### 2.1 Поведение врагов (Fluid Simulation)
- Количество: До 1000 врагов на экране
- Поведение: Моделирование жидкости
- Визуализация: Маленькие спрайты, объединенные в "поток"

### 2.2 Система стихий
- Базовые элементы: Огонь, Вода, Земля, Воздух
- Взаимодействие: Комбинации элементов (Огонь+Вода=Пар и т.д.)
- Применение: Тап + слайд пальцем по экрану
- Стоимость: Трата ресурсов (маны)

### 2.3 Структура экрана
- Поле боя: 5/6 высоты экрана
- Зона базы: 1/6 высоты экрана
- Ориентация: Портретная (вертикальная)
- Адаптивность: Под все размеры экранов

### 2.4 Зона базы и алтари стихий
- Алтари стихий: 4 иконки в зоне базы (Огонь, Вода, Земля, Воздух) для применения стихий.
  - Активация: Тап + слайд по экрану для рисования стихий.
  - Стоимость: Трата манны (конфигурируемый параметр).
- Иконка базы: Заменена на супер силу бога (круглая иконка с прогресс-баром).

### 2.5 Механика супер силы бога#### Общие принципы
- Игрок выступает в роли бога, карающего демонов молниями.
- Прототип: Без звуков.

#### Обычная атака бога (молния)
- Активация: Тап по монстрам на поле боя.
- Эффект: AOE-атака (по площади) - уничтожает настраиваемое количество монстров в зоне поражения.
  - Параметр: Конфигурируемый (для баланса), прокачивается в геймплее.
- Визуал: Белая вспышка (меньшего размера).
- Заполнение прогресс-бара: Каждое уничтожение монстра молнией заполняет круглый прогресс-бар (заполняется снизу вверх ярко-розовым/маджентой; пустой бар - черный с бледной иконкой). Полный бар легонько пульсирует и испускает легкие вспышки; в режиме супер силы кнопка увеличивается, пульсирует сильнее и светится.

#### Супер атака бога
- Активация:
  1. Прогресс-бар заполнен -> нажатие на него активирует режим супер силы.
  2. Следующий тап по полю боя -> срабатывание супер силы.
- Эффект: AOE-атака - все монстры в зоне поражения погибают.
  - Радиус зоны: Конфигурируемый параметр (для баланса), прокачивается в геймплее.
- Визуал: Белая вспышка (большего размера).
- Сброс прогресс-бара: После использования супер силы прогресс-бар полностью сбрасывается в 0.

#### Отмена супер силы
- Если игрок не использовал супер силу после активации режима:
  - Повторное нажатие на прогресс-бар отменяет активацию супер силы.
  - Следующие тапы по полю боя возвращаются к обычным молниям.

#### Параметры баланса (конфигурируемые)
| Параметр | Описание | Прокачка |
|----------|----------|----------|
| lightningKillCount | Количество монстров, уничтожаемых обычной молнией | Да |
| superRadius | Радиус зоны поражения супер силы | Да |
| superChargeRequired | Количество монстров для заполнения прогресс-бара | Нет (баланс) |

### 2.6 Уровни и условие победы
- Уровень N спавнит N x 100 монстров: уровень 1 = 100, каждый следующий +100.
- Доступно 50 уровней (50-й = 5000 монстров); победа на 50-м = экран ИГРА ПРОЙДЕНА.
- Победа на уровне: все монстры заспавнены и поле боя чисто (игрок убил всех, кого мог).
- Монстры, дошедшие до базы, списывают HP и исчезают - убить их уже нельзя, в зачистку не входят.
- HP базы сохраняется между уровнями (не восстанавливается); восстанавливается только при рестарте после GAME OVER.
- Заряд силы бога сбрасывается при смене уровня.
- Выбор уровня - в поп-апе настроек (строка Уровень, [-]/[+]); смена уровня перезапускает его: НОВЫЙ лабиринт (новый seed), поле чистится, HP базы восстанавливается.
- После победы тап по полю боя открывает следующий уровень (новый лабиринт + баннер УРОВЕНЬ N); после GAME OVER тап **сбрасывает прогресс на уровень 1** (свежая игра, HP базы восстанавливается). Надписи «Deus vivit» (победа) / «Deus mortuus est» (поражение) плавно гаснут через ~2 сек.

## 3. Технический стек

### Основной стек:
- Игровой движок: Phaser.js 3.55+ (WebGL)
- Язык: TypeScript 5.0+
- Сборщик: Vite 5.0+ с PWA плагином
- Архитектура: ECS (bitecs + miniplex)

### Для производительности:
- Web Workers для fluid simulation
- Object Pooling для переиспользования объектов
- Texture Atlas для спрайтов
- Batch Rendering в Phaser

### Для PWA:
- Service Workers для офлайн-работы
- Web App Manifest для установки
- IndexedDB для сохранения прогресса

## 4. План разработки (8 недель)

### Фаза 1: Базовый каркас (2 недели) - ЗАВЕРШЕНА
1. Настройка проекта (Vite + Phaser + TypeScript) - Готово
2. Адаптивная верстка (поле боя + зона базы) - Игровое поле 9:19.5, поле боя и зона базы с фиксированными пропорциями, центрируется на любом экране
3. Базовое движение врагов (100 врагов) - 1000+ врагов на экране, спавн над экраном, движение к базе без ускорения

### Фаза 2: Core геймплей (3 недели)
1. Генерация уровней по seed - Детерминированный лабиринт из органических блобов, 100% проходимость (BFS + прорезка коридоров), коллизии O(1), кнопка Сгенерировать уровень с новым seed. См. LEVEL_GENERATION.md
2. Fluid simulation через Web Workers
3. Система стихий (4 элемента + комбинации)
4. Рисование стихий пальцем
5. ✅ Механика супер силы бога (обычная молния + супер атака) - Тап по полю = AOE-молния (до lightningKillCount монстров, ближайшие), убийства заполняют круглый бар снизу вверх; тап по иконке при полном заряде включает режим супер силы, следующий тап = супер AOE (все в superRadius), повторный тап отменяет; белые вспышки (малая/большая); параметры в поп-апе настроек. См. src/game/god/

### Фаза 3: Полировка (3 недели)
1. PWA настройки (офлайн, иконки)
2. Простая система сохранения
3. Тестирование на мобильных устройствах
4. Балансировка и фиксы
5. Настройка параметров баланса (lightningKillCount, superRadius, superChargeRequired)

## 5. Целевые устройства

- Минимальные: Современные смартфоны (6 ГБ RAM)
- Целевой FPS: 60 FPS
- Управление: Touch-жесты (тап, слайд)

## 7. Текущий статус

Версия: 0.5.0-alpha
Статус: Фаза 1 - ЗАВЕРШЕНА; Фаза 2 - генерация, fluid, супер сила бога, уровни и система стихий (Итерации 1-4) готовы

### Что работает сейчас:
- Базовая настройка проекта (Vite + Phaser + TypeScript)
- Адаптивная верстка: игровое поле 9:19.5 с полем боя (5/6) и зоной базы (1/6), центрируется на любом экране
- Fluid simulation в Web Worker: SoA-память, spatial hash, силы жидкости (separation/pressure/viscosity/cohesion), антизастревание - 100% монстров доходят до базы, ~0.6 мс/шаг @1000 агентов
- Генерация уровней по seed: органический лабиринт, дренаж карманов, лимит кластеров, морфологическое открытие
- Параметры генерации в дебаг поп-апе: **плотность препятствий задаётся уровнем** (2.0 → 0 линейно, см. ниже), степпер «Плотность» — сессионный оверрайд (сбрасывается при смене уровня); «Размер структур» (x0.1-3.0) — ручная ручка, пересборка на лету с тем же seed
- Дефолты спавна: интервал 5мс, до 10000 монстров на экране, **скорость монстров задаётся уровнем** (0.3 → 0.8 линейно, степпер в поп-апе — сессионный оверрайд); **загон монстров** — полоса у верхней кромки поля боя с очередью оставшихся: вместимость плотной упаковки `penCapacity` (потолок `PEN_CAP_MAX`=1000), при остатке меньше вместимости — градиент от нижнего края (нижний ряд плотно, выше свободнее, спад 0.6), при большем — полная толпа; монстры выходят из загона на поле, толпа «течёт» вниз и редеет к хвосту (перераскладка при уходе, детерминированный джиттер); стихии/силы в загон не рисуются (без траты маны); верх полосы свободен от препятствий (topFreeHeight)
- **Индикатор здоровья базы — фронт инферно**: по мере потери HP базы текстура «инферно» (ground-inferno + fade) надвигается от загона вниз к базе; **проигрыш наступает только в момент контакта ground_inferno с ground_holy** (0 HP). Fade — чисто декорация: следует за фронтом и в конце спуска **прячется под святую землю** (глубины: ground 100 < holy-fade 106 < тело инферно 107 < inferno-fade 108 < ground_holy 110 < иконки базы 120 < монстры 850). Блобы выше фронта «поджигаются»: весь лабиринт запекается в ОДИН огненный слой (`obstacle-blob-inferno`, ручной шит художника, без процедурного фолбэка), который поверх обычных блобов вскрывается **двумя Bitmap-масками** — жёсткой «выше линии фронта» и градиентной полосой 24px у фронта (**размытая кромка**, ширина постоянна). Две маски на двух спрайтах — стоимость не зависит от числа блобов, FPS не страдает; граница перекраса непрерывная (без рывков по рядам); при сбросе уровня слой скрывается. Монстры рисуются поверх стихий (depth 850)
- Дебаг-панель (FPS/агенты/SimW мс/Земля) — **по умолчанию выключена**, тоггл «Дебаг-панель» в поп-апе ⚙; из поп-апа убраны ручки «Интервал спавна»/«Максимум на экране»/«Размер монстров» и кнопки сброса; силы жидкости остаются в GameConfig.enemies.fluid
- HiDPI-рендер: канвас в физических пикселях устройства, глобальные правила масштабирования UI
- PWA на GitHub Pages: Actions workflow, манифест, иконки, офлайн-кэш физики; превью фичевых веток (см. deploy.yml)
- Счетчик FPS, HP базы, количества монстров
- Условие победы (§2.6): система уровней 1-50 (уровень N = Nx100 монстров), выбор уровня в поп-апе, победа -> следующий уровень по тапу, баннер УРОВЕНЬ N, финал ИГРА ПРОЙДЕНА на 50-м. **Прогрессия по уровням (линейная):** монстры 100→5000 (шаг 100), скорость 0.3→0.8, плотность препятствий 2.0→0 (1-й уровень — узкие проходы, 50-й — пустое поле без препятствий)
- Супер сила бога (см. [GOD_POWER.md](./GOD_POWER.md)): тап по полю боя = молния (AOE, ближайшие lightningKillCount монстров), круглая иконка в центре зоны базы: пустой бар черный с бледной молнией, заряд маджентой наливается снизу вверх за убийства молниями; полный бар пульсирует и испускает вспышки-кольца; тап по иконке включает режим супер силы (кнопка увеличивается, яркое свечение), следующий тап по полю = супер AOE (все в superRadius), повторный тап по иконке отменяет режим; дефолты 2 убийства/молния, радиус супера 100, заряд 80 убийств (в поп-апе: lightningKillCount/superRadius/superChargeRequired); дебаг-хуки window.__di/__gc (только при game.debug) для смоук-тестов
- Система стихий, Итерации 1-4 (см. [ELEMENT_SYSTEM.md](./ELEMENT_SYSTEM.md)): независимая мана алтарей (ёмкость/gainPerKill/costPerUse в GameConfig.elements), наполнение от боевых убийств; тап по алтарю выбирает стихию (выбор сохраняется после штриха, сброс — тапом по полю/другим алтарём), ведение пальца рисует линию толщиной radius в цвет стихии, тап без движения = молния; мана списывается поюнитно в реальном времени (юнит elementStrokeUnit), при нехватке линия обрывается; препятствия не рисуются; **Земля-барьер**: непроходимые ячейки с прочностью на ячейку (bitesPerCell, прокачиваемая), монстры атакуют/гибнут и грызут (biteRadius), через дыры проходят; **базовые эффекты Огонь/Вода/Воздух (Итерация 4)**: горение с ограниченным цепным поджогом (burnRadius/spreadChance/maxIgnitePerDeath), замедление воды (slowFactor), отброс воздуха (pushStrength, направление жеста); статусы — перекраска tint (дефолт красный, горение оранжевый, мокрый синий); сброс маны/слоёв между уровнями; баланс в поп-апе + персистентность (TuningStore/localStorage)
