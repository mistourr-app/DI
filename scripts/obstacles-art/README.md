# Пайплайн арта препятствий (блоб-тайлсет)

Полный цикл: от рисунка художника до атласа в игре. Скрипты — в этой папке
и в `assets-src/` (нарезчик для художника).

## Быстрый цикл художника (основной путь)

Раскладка шита зафиксирована (Test2: 7×7 ячеек 16×16, маппинг вшит в нарезчик):

1. Обновить арт в шите (например `Test2.png`) — тот же порядок ячеек.
2. Перетащить PNG на **`assets-src/build_atlas.bat`** (двойной клик).
3. Готово: нарезанный атлас записан в `src/assets/obstacles_blob.png`.
4. Обновить страницу игры.

Никаких проверок соответствия шаблону — ответственность за раскладку на художнике.
Только очевидные ошибки (не PNG, нет файла) дают сообщение.

## Инферно-шит (огненный вариант блобов)

Блобы «поджигаются» фронтом инферно по мере потери HP базы: клетки выше
фронта переключаются на огненный атлас `obstacle-blob-inferno`. Пайплайн тот же:

1. Рисуешь инферно-варианты тайлов в **той же раскладке Test2 (7×7)**, огненной
   палитрой (уголь/оранж/жёлтый, искры).
2. Перетащить PNG на **`assets-src/build_atlas_inferno.bat`** — нарезка в
   `src/assets/obstacles_blob_inferno.png` (маппинг общий, нарезчик один).
3. Проверка стыков инферно-атласа: `node scripts/obstacles-art/atlas-check.cjs --inferno`.
4. Обновить страницу игры (**F5**; dev-сервер отдаёт новый арт сразу,
   собранная версия — после `npm run build`, хард-рефреш Ctrl+Shift+R из-за PWA).

Инферно-атлас — **только ручной шит художника** (процедурного фолбэка нет):
если файла не будет, блобы просто не поджигаются.

## Участники

- **Художник** — рисует тайлы и подписывает их номерами кадров.
- **Разработчик** (opencode) — распознаёт номера, собирает атлас, проверяет стыки.

---

## Шаг 1. Шаблон для рисования (разработчик, по запросу)

```
node scripts/obstacles-art/gen-blob-template.cjs
```

Требует собранную игру (`npm run build`) — шаблон строится из текущего процедурного атласа.
Результат:
- `assets-src/blob_template.png` — сетка 8×6 (ячейки 2×): силуэты с точной геометрией
  стыков, мини-схема соседей (■/□, оранжевый центр = рисуемый тайл), номер кадра,
  подпись сторон/углов (N E S W · NE SE SW NW), бинарная маска;
- `assets-src/blob_reference.png` — цветной референс.

## Шаг 2. Рисунок и подписи (художник)

1. Рисует тайлы **16×16** по шаблону (поверх силуэтов, свои цвета). **Кромки обязаны
   совпадать**: у всех тайлов с стороной N одинаковая верхняя кромка, с S — одинаковая
   нижняя, E/W — аналогично; углы кадров 4/34 (диагональные контакты) заполнены.
2. Кладёт шит в `assets-src/` (например `Test2.png`).
3. Подписывает каждую ячейку **номером кадра** (0..46 из шаблона) — отдельный лист
   `assets-src/Table.png`: та же сетка (7×7 или сколько ячеек), чёрные цифры на белом,
   по центру, крупно, печатные. Каждое число 0..46 — ровно один раз; дубли-копии
   одного тайла можно подписать одинаково (берётся первая).
4. Сообщает разработчику.

## Шаг 3. OCR подписей (разработчик)

```
node scripts/obstacles-art/ocr-table.cjs            # по умолчанию assets-src/Table.png
node scripts/obstacles-art/ocr-table.cjs assets-src/MyTable.png
```

Распознаёт цифры (эталоны Arial/Verdana/Courier), пишет `scripts/obstacles-art/mapping.json`
и отчёт с уверенностью. **Низкая уверенность или несостыковки с формой тайлов —
сверяются с художником.** Полезный контроль: стороны маски кадра должны совпадать
с кромками тайла.

## Шаг 4. Сборка атласа (художник или разработчик)

**Художник (основной путь, маппинг фиксирован):** перетащить шит на
`assets-src/build_atlas.bat` — нарезка без участия разработчика.

**Разработчик (новый шит / другой маппинг):**

```
node scripts/obstacles-art/reorder.cjs                              # шит по умолчанию assets-src/sheet.png
node scripts/obstacles-art/reorder.cjs assets-src/Test2.png
```

Складывает тайлы шита в канонический атлас **8×6** (кадр = маска по возрастанию)
и пишет `src/assets/obstacles_blob.png`. Дубли кадров — берётся первая ячейка.
Недостающие кадры → ошибка (дорисовать/поправить маппинг).

> Нарезчик `assets-src/build-atlas.cjs` — тот же функционал для фиксированного
> маппинга Test2, ноль зависимостей (встроенный PNG-кодек). Маппинг вшит в файл
> (`CELL_TO_FRAME`) — при смене раскладки шита обновляется и он.

> При необходимости маппинг можно поправить вручную: отредактировать
> `scripts/obstacles-art/mapping.json` (массив `cellToFrame`) и перезапустить шаг 4.

## Шаг 5. Проверка стыков (разработчик)

```
npm run build
node scripts/obstacles-art/atlas-check.cjs          # обычный атлас
node scripts/obstacles-art/atlas-check.cjs --inferno # огненный атлас
```

Попиксельно сверяет стыкуемые кромки кадров:
- **ШВЫ** — кромки кадра vs кромка кадра «сдвинутой» маски (средние 12px);
- **ДЫРЫ** — обе стороны стыка пустые (зазор);
- **УГЛЫ** — 2×2 блока у диагональных контактов заполнены.

Цель — 0 проблем. Замечания → художник правит арт → повтор шагов 4–5.

## Шаг 6. Интеграция в игру

Атлас `src/assets/obstacles_blob.png` подключается автоматически:
`GameScene.preload()` → `this.load.spritesheet('obstacle-blob', ...)`.
Процедурный атлас (`blobAtlas.ts`) — фолбэк, если файла нет.
Выбор кадров (`blobTiles.ts`, 47 масок) не зависит от арта.

## Спека атласа (кратко)

| Параметр | Значение |
|---|---|
| Файл | `src/assets/obstacles_blob.png` |
| Размер | 128×128, 47 кадров 16×16 |
| Раскладка | 8 колонок × 6 рядов (48-й слот пустой) |
| Порядок | кадр `i` = каноническая маска №`i` по возрастанию (кадр 0 = круг, 46 = полный) |
| Стыки | полудиск на крае тайла = полудиск соседа; четверть-диски углов общие |
| Цвет | любой (tint не используется) |

Полная спека — `docs/GRAPHICS_IMPORT.md` §6.1.

## Связь с кодом

- `src/game/visuals/blobTiles.ts` — выбор кадра по 8 соседям (47 масок), кромки поля
- `src/game/visuals/blobAtlas.ts` — процедурный фолбэк-атлас
- `src/scenes/GameScene.ts` — `preload()` (spritesheet) и `renderObstacles()` (спрайты по сетке)
